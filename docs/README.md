# PluginSDK documentation

PluginSDK packages shared skills and MCP connections for Claude Code and Codex. Keep one definition and its content, preview changes locally, then publish a release for your team.

Start with [Get started](getting-started.md). The tutorial builds a release notes plugin that works against your repository without an external service.

| Your task | Guide |
| --- | --- |
| Build and use your first plugin | [Get started](getting-started.md) |
| Add skills, MCP servers, hooks or agents | [Define a plugin](authoring.md) |
| Preview locally and publish to your team | [Publish a plugin](publishing.md) |
| Install, update, remove or repair a plugin | [Manage installations](usage.md) |
| Centralize integrations for a team | [Manage plugins for a team](teams.md) |
| Retain an approved version | [Manage approved releases](catalog-usage.md) |
| Apply one release to several destinations | [Distribute a release](distribution-usage.md) |
| Check client and platform support | [Supported clients](compatibility.md) |
| Resolve a failed review or installation | [Troubleshooting](troubleshooting.md) |

The [examples](../examples/README.md) show the files a plugin author maintains. The [internals](internals/README.md) describe how PluginSDK is implemented and verified.
