# Windows Claude project query acceptance

Claude Code 2.1.304 on Windows x64 completed the candidate SDK project lifecycle: install, unchanged planning, replay, replacement, removal, and absent planning. A plan for a second project had a distinct physical target identity and was never applied. The public Windows project profile remains disabled pending interruption recovery and compiled CLI qualification.

The experiment queried two Git project roots under one isolated home. After installation and replacement, A reported the owned plugin with `scope: project`, `projectPath: A`, `enabled: true`, and `projectEnabled: true`. B listed the same installation with `projectPath: A`, `enabled: false`, and `projectEnabled: false`. Both roots listed the home marketplace. After removal, both plugin and marketplace inventories were empty. Inventory visibility therefore cannot stand in for activation in a project.

A's plugin details listed both exact authored skill names. Each installed payload matched all nine planned files byte for byte, including the replacement generation. Only the owned plugin selector and directory marketplace entries changed in A's settings. User and B settings remained byte-exact, and A's unrelated settings were preserved.

Independent validation covered 11 caller processes, 11 transaction workers, 14 native queries in six groups, and 84 retained query process births. Each query birth had an admitted image and creation identity, a terminal wait, and a closed handle. Cleanup consumed that validation receipt, checked the complete final inventory, and removed 5,287 files totaling 420,845,794 bytes. The four previously unknown roots were untouched.

The evidence is under `.audit/probes/windows-claude-project-query-v2/`. `project-query-validation.json` records the retained files and completion checks; `cleanup.json` records guarded removal. `acceptance.json` seals these artifacts against the preceding diagnostic checkpoint. No public runtime source changed in this experiment.

This establishes normal SDK lifecycle and native inventory behavior for the candidate profile. It does not qualify interruption recovery, compiled project CLI execution, model-driven tool invocation, or remote MCP authentication. macOS has no available host. Grok native tests, third-party authentication, CI, and package/release-wide checks remain deferred.
