# Portable feature compiler acceptance

The compiler builds `claude_code_portable_v2` and `codex_plugin_portable_v2` from the existing definition. These formats combine MCP, synchronous `SessionStart` and `UserPromptSubmit` hooks, assets and the existing agent documents. Both process components share one packaged runtime. The older formats retain their meanings.

This accepts compiler integration and local process execution. Native client lifecycle qualification and profile/default promotion remain open. Normal `build` still selects the previously qualified formats.

## Formal and pure gate

The [design](portable-features-compiler-design.md) extends the closed Lean catalog format and digest types, exact lookup, artifact enumeration, strict wire codecs and host compatibility. The existing universal proofs rebuild and pass the exact-type and axiom audit: 310/310. No new axiom or proof exception is used.

Thirty-six independently authored [format vectors](../../spec/vectors/portable-feature-formats.ndjson) match Lean before TypeScript changes. They cover immutable catalog registration, digest conflict, exact resolution, missing cross-version formats, artifact integrity, v1 substitution, host selection, ambiguity and exact synthetic profile matching. The extended Effect contracts and exhaustive distribution selection then pass those cases, the original 30 portable-format cases and five malformed-wire pairs before I/O changes.

The [proved shared renderer](portable-feature-composition-acceptance.md) remains the owner of host agreement, complete diagnostics, both native documents, ordered descriptors/sidecars and runtime cardinality.

## Compiler and Installer integration

`materializeProcesses` consumes the shared result for v2 and owns file-role serialization and runtime reads. It replaces the MCP-only materializer while retaining the older renderers for older encodings. The compiler adds the two documents and generated files before its existing assembly and digest checks.

The common portable process validator strictly decodes shared `ProcessData`, reconstructs its canonical program and checks the exact sidecar and file roles. MCP validation retains its server and capture rules. Hook validation checks the complete native binding against `bindHook`, strict event groups, timeout, synchronous execution and unique contiguous ordinals. Both hosts reject hook environment captures.

`BundleMetadata.processes` now retains each descriptor path with its script. Directory admission consequently checks hooks and reports their actual paths. Runtime admission recognizes the new portable encoding. Codex companion extraction and retained-agent qualification use the existing host/agent capabilities instead of enumerating older format names. No native profile is added.

Ordinary unreferenced assets under `.psdk` remain allowed by the existing asset contract. Validation does not interpret them as process declarations. Referenced descriptors and sidecars still require exact validation.

## Scoped checks

All 50 tests in twelve scoped suites pass. The eight new compiler tests cover:

- Deterministic mixed packages, enumeration invariance, shared names, one runtime, exact hook documents, complete process metadata and unchanged agent/companion bytes.
- Identical v1/v2 MCP-only package files, empty and remote-only preservation, and hook-only packages.
- Complete MCP/hook collision diagnostics and hook environment-reference refusal during both build and native package validation.
- Twenty-eight malformed native event/binding cases and twenty-six descriptor/sidecar/runtime refusal cases across both hosts. The latter count includes the two captured-hook cases.
- Ordinary descriptor-shaped assets remaining outside process admission.
- Two local Linux executions of SDK-compiled hook descriptors with UTF-8/spaced roots, exact stdin and literal arguments, empty environment values, packaged working directories and exit status 7.
- Every existing native profile remaining unqualified for v2.

Existing MCP, hook, agent, companion, profile, format-selector, runtime and directory-admission regressions also pass. The actual Linux runtime-admission check additionally accepts both new encodings. Strict TypeScript checks, Effect diagnostics on 27 scoped files and lint pass.

The first test run exposed missing required headers in the new fixture. Subsequent checks corrected a Buffer/Uint8Array comparison and an unsupported assumption that all unreferenced `.psdk` assets must be rejected. Static checking also corrected one typed decoder and the scoped config's omission of an existing ambient declaration. Failure logs and the main review remain in the checkpoint.

Compare generated bytes when the next native gate prepares its packages; earlier runtime evidence applies only to its recorded artifact.

Public profiles and automatic format selection remain byte-for-byte unchanged. No Windows scratch roots were inspected or modified. macOS, Grok native tests, third-party authentication, CI and release checks remain deferred.
