A private Claude Code 2.1.304 portable v2 candidate passes nine project recovery cases on Linux. A fresh SDK caller settles an interrupted operation without repeating its native change. The selected project retains the expected generation or fresh absence; another project sharing the client home remains unaffected. This checkpoint keeps production profiles unchanged. The subsequent [stdio-only project qualification](portable-project-stdio-linux-acceptance.md) enables both portable formats for this Linux project profile.

This extends the [normal project lifecycle](portable-features-project-linux-acceptance.md). The [selected recovery design](../../.audit/probes/portable-features-project-recovery/design.md) keeps the existing definition, build, destination and reviewed plan/apply interfaces. All 183 production source files retain their preceding hashes. The existing 318-proof checkpoint, 336 profile-oracle comparisons and 31 scoped product tests are carried forward. This phase adds native evidence without a new model or public schema.

## Interrupted operations

| Cut | Fresh recovery result | Accepted behavior |
| --- | --- | --- |
| Before install | `not_applied` | Plugin remains absent. |
| After install | `installed` | Receipt binds the original reviewed plan and bundle. |
| Before replacement | `not_applied` | Previous generation remains usable. |
| After replacement | `installed` | New generation is usable with its reviewed identity. |
| Before removal | `not_applied` | Previous generation remains usable. |
| After removal | `removed` | Fresh native inference has no plugin tools, role or context. |
| Caller dies before installation; worker resumes | `installed` | Worker retains both leases, blocks competing writers, then finishes once. |
| Caller dies after installation; worker resumes | `installed` | Worker finishes; fresh recovery settles the retained pending plan. |
| Removal stops after plugin uninstall | `uncertain` | A separately reviewed marketplace-only repair removes the residual once. |

Each cut retains the complete pending plan and separate caller/worker birth witnesses. Terminating the caller leaves its native worker active with both home and project lock descriptors. Recovery begins after worker completion or termination and reaping. The worker leaves the journal pending; the fresh SDK caller owns settlement.

In the before-install survival case, two fresh callers contend for the inherited home and project leases. Both remain blocked until the worker is released. After completion, the same-project caller using another home returns `blocked/unowned`; the other-project caller returns a ready plan, which is never applied.

Recovery and replay leave native configuration unchanged and do not enter native execution again. The partial uninstall stays uncertain. Its distinct repair plan runs once, repair replay adds no mutation, and the superseded original plan returns typed `stale_plan`.
