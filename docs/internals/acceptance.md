## Limits

The Lean proofs cover pure policy. Filesystem truth, hash implementations, process quiescence and durable storage remain checked I/O assumptions. Process-kill tests do not simulate machine power loss. SDK locks coordinate SDK writers; arbitrary external host edits are outside that lock.

Distribution storage retains complete reviews and outcomes under a trusted physical Linux directory with cooperating SDK writers. Existing missing/corrupt records fail without reset. A completed result is historical; replay does not continuously reinspect terminal destinations. An unchanged operation does recheck its basis before first completion. Distribution makes no cross-client rollback, continuous-health, workspace-administration or backend-permission guarantee.

The [organization authorization model](authorization-design.md) proves identity, freshness, exact tool grants and required restrictions over supplied evidence. It does not establish that a token was verified or that a service enforces its result. The [catalog model](catalog-design.md) proves immutable admission and exact selection through its pure transitions. `ReleaseCatalog` adds verified local Linux plugin-package and reviewed-contract retention under a trusted store and cooperating SDK writers. Artifact import verifies the approved archive pin; it depends on trusted release metadata and does not authenticate its publisher or protect against arbitrary external rewriting. Each store operation reads the complete catalog; new admissions rewrite it. Imports fetch again and use a 64 MiB/30-second bound, HTTPS or loopback HTTP, no redirects and no ambient credentials. Schema-1 plugin stores are read without rewriting during initialization, acquisition or unchanged replay. A successful new admission writes complete schema 2; older SDK versions cannot read it. Missing/corrupt existing storage fails instead of resetting history. A process killed before rename can leave a complete orphan temporary file; automatic collection and interrupted-initialization recovery are not implemented. Repository acquisition, credential integration, workspace distribution, existing-service adapters and end-to-end revocation latency remain open.

Claude's exposed inspection commands establish MCP connection and tool discovery. The harness does not claim a Claude model-driven tool call. Codex's direct app-server tool call needs no model turn. Neither fixture proves third-party OAuth or credential availability.

Versions and platforms outside the [support table](../compatibility.md) remain unqualified. [Codex project acceptance](codex-project-acceptance.md) qualifies basic packages on Linux with 0.163.0. The Windows [project](windows-project-cli-acceptance.md) and [user](windows-codex-user-acceptance.md) records qualify that version with `agent_plugins_v2` on Windows x64. [Windows Claude user installation and preview](windows-claude-user-acceptance.md) qualify 2.1.304 with `claude_code_v2`. macOS is deferred because no real host is available. Grok Bot and Meta Muse return `DestinationUnsupported`; [host research](host-research.md) records the missing contracts. ChatGPT, Cursor and organization management remain the planned [organization design](organization-design.md). A partial native recipe can remain pending and uncertain. Explicit reviewed repair handles qualified absence, orphaned marketplaces and exact owned companion residuals; automatic retry or rollback is outside the alpha.

Bundled stdio currently qualifies Linux user scope on both pinned clients. Claude project-scope stdio needs its own acceptance. V3 installation checks `/bin/sh` and GNU `/usr/bin/env` 9.4; authors supply their application runtime and captured dependencies. The native fixture copies the example server and adds an external trace wrapper in a temporary source tree. It does not instrument the authored example.

Hooks qualify synchronous `SessionStart` and `UserPromptSubmit` on the pinned Linux user profiles with the [recorded fixture limits](hooks-design.md#sdk-lifecycle-qualification). Codex's native format also checks GNU `/bin/pwd` 9.4. Its hook trust can remain valid when a referenced policy program changes, and the hostile-path probe disabled shell snapshots. Other events and project-scope hooks remain open.

Shared agent authoring and owned Codex role-file lifecycle are qualified on the newer Linux user profiles. One definition builds both packages; actual child requests preserve the prompt and selected native model, and forced disabled shell calls reject without a sentinel write. Updated prompts/models/policy appear in fresh children. Install, replacement, removal, replay, drift/collision rejection and both companion repair cases pass through the compiled SDK CLI. This is native tool exclusion, not OS sandbox enforcement or backend authorization. Other controls and scopes remain open; see the [complete agent record](agents-design.md#native-acceptance).
