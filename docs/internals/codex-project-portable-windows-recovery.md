## Caller, worker and lease ownership

At each selected checkpoint, caller and transaction worker have distinct retained PID/creation identities and exact staged Node images. The fixture terminates the caller first. The worker remains active, and both home and project lock-owner records still identify that worker.

Six independent Windows lock probes run per case: both locks reject acquisition before caller termination and after caller termination, then permit acquisition after worker completion. Every probe descriptor closes; successful probes explicitly unlock. All 96 probes pass.

Terminated workers leave their pending state unchanged. Resumed Windows transaction workers complete engine settlement themselves, despite caller loss. Their installed receipt survives recovery and replay. Every controlled process handle requires a terminal observation and successful close; all 32 controls pass.

## Recovery behavior

Private observations record execution entry and checkpoints immediately before and after the real project config replacement. The Windows atomic replacement implementation is unchanged. Recovery and replay add no execution or publication event. Stored state, native config bytes, Windows attributes/security digests and backend event logs are checked across those operations.

Read-only client inspection remains permitted through exact version, feature-listing and plugins-disabled app-server probes. Recovery launches no bundled process and makes no inference request. Inactive project repair uses a new reviewed decision with zero native execution entries; its replay is idempotent, and the original install plan is then rejected as stale. Captured prepared caches and retained revisions remain byte-identical, including inactive revisions.

## Counterexamples and retention

Two failed runs remain preserved. The first resumed its worker but exhausted a ten-second process-control wait before natural completion. Its seventy retained identities reached termination and all handles closed. A separate successor raises that fixture wait to 45 seconds while preserving the sixty-second command limit, process identity checks and terminal-close requirements. Both formats pass that successor.

The second returned `DestinationUnsupported` from the SDK's bounded Node-runtime check before any execution entry. Its 49 retained identities closed. The public probe did not record whether failure came from its timeout or output check, so the precise cause is unproved. Fresh repair cases pass with native jobs serialized. The refused run contributes no repair evidence.

Each accepted case retains independent complete runtime copies and passes exact native inventory comparison before cleanup. All sixteen accepted roots are removed. The two failed roots remain intact without post-failure inventory or cleanup. An unused prepared root is removed after exact inventory verification without launching a client.
