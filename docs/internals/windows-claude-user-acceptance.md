# Windows Claude user acceptance

Claude Code 2.1.304 on Windows x64 supports user installation and preview with `claude_code_v2`. The package contains skills, supporting files and remote HTTP MCP declarations. Native qualification used Node 24.18.0. The [support table](../compatibility.md) records the available versions and scopes.

The public change adds one exact profile. Pure models, schemas, compiler behavior and installer execution remain unchanged. All nine predecessor profiles remain registered.

| Interruption recovery | Seven cases pass across 358 steps, 36 callers, 36 workers and 36 discovery groups. All 600 observed discovery process births have exact identities, terminal waits and confirmed handle closure. |
| Compiled CLI lifecycle | Seventeen commands build twice, review and apply installation, replacement and removal, replay each plan and verify unchanged planning. Twelve workers perform three executions. Six discovery groups contain sixteen native queries and 96 process births. |

Replay preserves configuration and journal bytes. Unrelated user settings and both project settings files survive unchanged. |

The [raw recovery receipt](../../.audit/probes/windows-claude-user-v3/acceptance.json) seals the seven interruption cases. The [CLI and promotion receipt](../../.audit/probes/windows-claude-user-cli/acceptance.json) binds that receipt to compiled commands, preview, cleanup and the public profile. Each case retains its own independent validation and evidence hashes.

A controller assertion failed before the first compiled native launch. The [prelaunch correction](../../.audit/probes/windows-claude-user-cli/prelaunch-correction.json) preserves the original controller, stage record and manifest evidence. The corrected guard checks that the temporary Codex environment variable is removed before launch. All 5,201 staged files remain unchanged, and both native CLI cases run once under that corrected controller.

Native discovery verifies Claude's installed metadata, approved payload folder, exact skill inventory and MCP declarations. These checks do not establish an MCP connection, a model-driven tool call or third-party authentication. Windows Claude project installation, bundled stdio, hooks, agents and source symbolic-link coverage remain unqualified. Earlier stages with unknown process completion remain isolated and untouched.

macOS remains deferred because no host is available. Grok native tests, third-party authentication, CI, package-consumer checks and release-wide acceptance remain deferred.
