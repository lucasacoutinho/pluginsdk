# Current-contract consolidation acceptance

The compiler, catalog, compatibility policy and ordinary callers now use one current representation per package client. There are no deployed installations or migration obligations. This record accepts the scoped implementation. The [Cursor author workflow](cursor-author-current-acceptance.md) and [Windows manager lifecycle](windows-manager-current-acceptance.md) also have current native acceptance.

## Resulting behavior

`Compiler.Format` is `claude_code | codex`. Claude and Codex each have one manifest/MCP renderer and one shared portable process path. Cursor selects the Claude package. The feature-to-generation selector, old shell-only composition, generic Agent Plugins schemas, fallback validators and their obsolete proof/vector operations are removed. Native agents, both supported hook events, assets, executable intent and complete bundle validation remain.

Installer selects a unique host/platform/scope/format adapter supporting all capabilities derived from the validated bundle. An observed app version is diagnostic evidence. Its change alone does not stale a review or abandon an owned package. Physical identity, native response contracts, installed bytes, reviewed configuration, adapter revision and pending-operation rules remain enforced. Runtime prerequisites still include Node 24.18+ for bundled commands and actual Linux shell/environment behavior; there is no exact helper-version allowlist.

Catalog has one strict schema-2 tagged-entry reader. It refuses obsolete or corrupt records without rewriting them. It retains immutable admission, complete artifact binding, conflict, replay, concurrent-writer and acquisition checks.

Authors use `build [definition.json] [--target CLIENT]`, `preview` and configuration-derived `publish`. Every build writes client bundles and `build.json`. There is no author `build --format` branch or SDK wrapper.

## LDD and scoped checks

The sequence was property and Lean model, exact-type/transitive-axiom audit, independent oracle vectors, pure TypeScript conformance, then I/O. The pure checkpoint accepts 54 affected core properties plus 4 launcher properties. It permits only Lean's standard axioms and contains no admitted proofs. The original canonical oracle remains unchanged; the consolidation uses its separately built oracle.

The pure TypeScript gate passed nine suites with 35 tests. Independent expectations exposed two stale Codex manifest examples; those were corrected to the selected native contract rather than filtering invalid frames. Formal TypeScript refinement remains unproved.

Scoped I/O suites cover compiler boundaries, current native documents, complete processes, assets, hooks and agents; catalog/CLI persistence; author build and local Git publication; Distribution planning and per-target results; installer ownership, companion capture, repair storage and preview routing. Main reviewed the artifacts, corrected stale scope expectations and fixture typing, removed a structural cast, restored independent absent-project-config coverage, and independently ran the critical compiler, catalog, runtime, CLI and Distribution paths.

The final affected-file typecheck passes. Effect diagnostics checked all 89 selected roots with zero errors, warnings or messages. Scoped lint and diff checks pass. Native fixture updates are statically checked; that does not claim their execution.

Main's subsequent review found two remaining diagnostic-version comparisons: Distribution's unchanged verification and Installer's pending-record lookup. Focused checks now accept a version-only observation change while preserving the exact saved records; tampered commitments and changed adapter identities still reject. The pending-record case reproduced the previous failure before its correction. These I/O projections implement the already selected model; they introduce no new lifecycle transition or permission to repeat an uncertain mutation.

Evidence is retained under `.audit/probes/prelaunch-consolidation/`: `pure-main-checked.json`, `io-main-checked.json`, the subsequent version-projection receipt, the bounded worker reports, the compiled candidate receipt and example/pilot receipts. Failed initial expectations and their corrections are recorded separately from successful results. Full CI, package-consumer and release gates were not run.
