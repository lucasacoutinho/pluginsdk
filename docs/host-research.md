# Host research: Grok Bot and Meta Muse

Public-source review accessed 2026-10-20. Scope is xAI's Grok Bot and Meta's personal AI agent Muse. Muse Code is excluded. I did not sign in, submit connectors, call product APIs, or change host configuration. The current design expects adapters to inspect native state, identify a physical installation, and prove ownership from a receipt plus a matching observation ([design](design.md)).

## Blocking contract gaps for the current installer

For Grok Bot, public docs establish app-managed discovery, installation, inspection, and removal, plus a publisher intake path. They do not publish the native catalog record or package schema, an extension version/profile contract, a stable install identity, or a machine-readable operation to inspect and reconcile installed state. The documented UI list is not enough to produce the design's verifiable before-state and matching ownership receipt.

For Muse, public docs establish a real third-party connector program over API or MCP, user-level authorization, review, directory discovery, and UI disconnection. The accessible guidelines do not define the host-side connector schema or protocol/version negotiation, stable installed connector identity, or machine-readable list/inspect/install/remove operations. The authenticated submission portal may expose more details; this pass did not access it. The guidelines also mark tool permission annotations in the portal as “coming soon,” with developers asked to describe them in API/MCP documentation meanwhile.

These findings support product-level connector or marketplace targets, but the public evidence does not yet supply the native observation and operation contracts required for `Installer.plan`/`apply` to prove ownership, detect changes, and recover a pending operation. No adapter types or availability claims are inferred from the UI flows.
